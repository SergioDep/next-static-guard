## Analysis pipeline

1. Validate arguments, JSON policy, and root. Discover apps and entries; determine dependency versions using the snapshot rules below.
2. Read UTF-8 sources with TypeScript 6.0.3 (`allowJs`, JSX preserve, no emit). Create SourceFiles and an isolated Program with a read-only host; use the checker for symbol identity, not as a runtime oracle. Do not diagnose general type errors in the project.
3. Build a runtime graph, type map, and data edges. Each node has a relative POSIX path, hash, and directives; edges have a symbol, kind, phase, and position. Resolve cycles with a worklist to a fixed point.
4. Propagate contexts by use, classify values, and execute NSG001 through NSG006 over shared facts.
5. Group evidence, assign identity, compare the base, apply exceptions and blocking; emit formats and the final exit code. Stable ordering by file, offset, and rule.

### Snapshot and version identity

Each snapshot provides a sorted path inventory, byte reads, metadata reads, and symlink resolution. The engine receives immutable maps of sources, manifests, configs, app profiles, and read limitations; it never reads the live filesystem. Source hashes are SHA-256 of original UTF-8 bytes. Reject invalid UTF-8 with `unsupported-syntax`; preserve line endings for locations. Read each file once per snapshot. If size or modification metadata changes during a filesystem read, return operational error 2 instead of mixing revisions.

Filesystem version lookup uses the installed package.json for next/react/react-dom/typescript resolved from the app, then the nearest ancestor npm v3 lockfile within the scan root, then an exact dependency version in the app manifest. Only package metadata may be read from node_modules. Lock lookup searches packages entries for app-local node_modules and then ancestor node_modules in resolution order. Ranges, aliases, missing entries, or conflicting installed/locked versions produce unknown versions; unknown Next/React/React DOM yields `unsupported-version`. Unknown project TypeScript remains informational. Git snapshots use their own lockfile/manifests and never current node_modules. React DOM must match React; record both in projects. TypeScript is informational: the tool always parses with 6.0.3; an older project TypeScript does not itself invalidate the framework profile.

Profiles are keyed by app root, snapshot, Next version, React/React DOM version, and effective runtime resolver config. A shared file can have different resolved edges in two apps. Known Next/React summaries apply only within the supported profile; an unsupported app produces `unsupported-version` and no rule findings. Other supported apps in the same scan continue normally. Coverage includes reached sources, evaluated entry exports, and required metadata; unrelated helper files are not implicitly certified as reviewed.

## Resolution and context

The only v0.1 profile is **Next 16.3.8 App Router with standard Turbopack**. Resolution does not attempt to simulate every configuration. Unmodeled destinations produce partial coverage. [S23](RESEARCH.md#s23)

`projectRoots` identifies apps under the scan root; also discover apps in declared npm workspaces within that root and deduplicate them by realpath. In each app, use `app` if present, otherwise `src/app`; if both exist, record the latter as ignored. Recursively discover page, layout, template, default, loading, not-found, forbidden, and unauthorized with `.js`, `.jsx`, `.ts`, and `.tsx` extensions as RSC entries; `.mjs` supports helpers only. error/global-error require a valid `use client` directive; a missing or invalid directive produces `unsupported-syntax` instead of leaving the entry unreachable. Route Handlers (`route`) and Server Functions use server context without RSC rendering. A file without known entries or consumers remains `unreachable`, with no boundary violations. Metadata files and the exported `generateMetadata`, `generateViewport`, `generateStaticParams`, and `generateImageMetadata` bodies, Proxy, instrumentation, Pages Router, and Edge are listed as out of scope; Edge detected through a literal `runtime = 'edge'` export limits that route's traversal. [S19](RESEARCH.md#s19)

Use contexts: `rsc`, `client-ssr`, `client-browser`, `server-function`, `server-handler`, `unreachable`, `unknown`. When crossing `use client`, stop RSC propagation and create client uses with possible SSR. When importing a valid module-level Server Function from the client, create a reference edge and analyze its body as server code. Require a directive in the initial string-literal prologue, an explicitly async function declaration/expression/arrow with a body, and a resolvable export. Comments/shebang and earlier string directives such as `use strict` are allowed; imports, ordinary statements, parentheses, and template literals do not form a valid boundary directive. Type-only exports are ignored; reexports of resolved valid Server Functions are accepted. Runtime constants, classes, unresolved wrappers, conflicting directives, and non-async exports produce `unsupported-syntax`; do not traverse their bodies as client code. A valid inline Server Function can cross as a prop, but cannot be imported from a client module. `use server` does not turn ordinary functions into Server Components. [S30](RESEARCH.md#s30)

Resolve specifiers in this order: known React/Next/marker summary; relative or absolute path within the root; paths alias from the consuming app config; baseUrl lookup; npm workspace name; unknown external package. For paths, try exact matches first, then the longest-prefix pattern, with at most one `*`, and destinations in order. Relative paths are based on the declaring config, honoring extends and baseUrl. Read tsconfig/jsconfig as JSONC. The consuming app uses literal `typescript.tsconfigPath`, otherwise app-root tsconfig.json, otherwise jsconfig.json. If neither exists, use no paths. Shared sources keep a separate resolution per consuming app; a nested config does not replace an existing app config. Relative extends are supported inside the snapshot; package extends, circular/unreadable extends, `#imports`, HTTP imports, and CommonJS produce limitations. Turbopack runtime resolution retains baseUrl lookups even though TypeScript 6 deprecates that behavior in its checker. [S27](RESEARCH.md#s27)

Local runtime: exact files before extensions; for extensionless paths, try `.tsx`, `.ts`, `.jsx`, `.js`, `.mjs`, `.json`, then a directory with `index` in the same order. Parse `.mjs` as JS ESM; `.cjs`, `.cts`, and `.mts` are outside v0.1. A JSON literal is serializable if its contents are. With effective `moduleResolution: nodenext` (case-insensitive), Turbopack substitutes explicit `.js` requests in order `.ts`, `.tsx`, `.js`, and `.mjs` in order `.mts`, `.mjs`. If `.mts` wins, emit `unsupported-syntax`; do not fall back to a different runtime file. In other modes, explicit extensions resolve literally. This substitution comes from the bundler profile, not the TypeScript checker. [S27](RESEARCH.md#s27) `.d.ts` provides type identity, never an execution edge. [S18](RESEARCH.md#s18), [S23](RESEARCH.md#s23)

Workspaces: read the root's `package.json.workspaces` (array or `packages`), discover their manifests and names. Automatic workspace discovery uses the npm workspaces field. pnpm/yarn workspace files and lockfiles are outside v0.1; those projects require explicit projectRoots/paths and exact supported dependency versions in installed metadata or manifests. Local exports: a string or exact subpath; objects with `import` and/or `default`, preserving order. Other conditions, export patterns, a browser field, and ambiguous duplicate package names produce `conditional-resolution`. A subpath absent from exports is unresolved, without falling back to main or bypassing encapsulation. Without exports, use module and then main only if they point unambiguously to accessible ESM; if they diverge, report a limitation. Do not traverse all of node_modules.

Statically recognize `next.config.js`, `.mjs`, and `.ts` with `export default` or, for `.js` only, `module.exports` assigned a literal object or unmutated local const object. This config-only recognition does not enable CommonJS application analysis. Read `env`, `pageExtensions`, `turbopack`, `webpack`, `experimental.extensionAlias`, `typescript.tsconfigPath`, and `transpilePackages`. Use defaults when no config exists. Unresolvable wrappers/functions/spreads produce `dynamic-config`. An empty turbopack object and pageExtensions containing only js/jsx/ts/tsx are supported. A transpilePackages list of resolved local workspace packages is supported. Custom resolution, loaders, unknown transpiled packages, or other page extensions limit the affected app in v0.1; do not execute them or implement plugins. Recognized CSS imports, static images, and fonts are framework resource leaves, not unknown JS modules; custom transformations do produce limitations.

Exclude explicit type imports/exports and type-only specifiers. Determine TypeScript import retention with the consuming app's effective `verbatimModuleSyntax` (boolean, default false, inherited through supported relative extends). With false, remove bindings with no unshadowed runtime use; a declaration whose bindings are all removed creates no dependency. With true, retain ordinary import declarations, including unused and implicit type bindings. JavaScript ordinary imports and retained runtime reexports preserve module dependencies, including unconsumed barrel exports. An invalid or unresolved retention setting produces `dynamic-config`. Track consumed value exports separately: an unconsumed export does not execute its function body, but its module restrictions still apply. Preserve side-effect imports and prologues. Resolve reexported values by the selected symbol; unknown export identity produces `uncertain-runtime`. Do not infer module elimination from unused names or assume an unconsumed value was published. [S30](RESEARCH.md#s30) A literal dynamic import has a known destination and propagated phase; a computed import or bundler import magic comment produces `unresolved-import`. Unmodeled Next/React APIs produce `unknown-phase` or `unknown-value` only when their semantics are needed to evaluate a supported rule; importing an unrelated symbol alone is not a limitation. NSG001 requires a module restriction, a retained restricted API import, or resolved API use from the exact summary table; a similar package name is insufficient.

## Execution phases and data flow

Ruleset 1.1.0 preserves declared export sensitivity across default exports and reexport aliases. React elements carry the data of their props and children. For a resolved Server Component element, bounded evaluation follows its rendered result; its inputs remain on the server. Unknown component results use `unknown-value`. A call to an imported Client Function from server execution has an unknown result; its client implementation is not evaluated as server code. Filesystem namespace imports, retained reexports, and executed literal dynamic imports retain the server-only restriction. Explicit exports take precedence over star reexports when resolving value identity.

Direct local calls include declared functions, function expressions, arrows, and methods or function-valued properties of an unmutated object literal. Property selection requires a static name, including a literal bracket key. An unknown spread or computed key that can replace the selected property, an unresolved call, or a mutation that invalidates the callee produces `unknown-phase`; class component execution is outside this model. The same call-depth budget applies across these forms.

Phases: module evaluation, render, state initializer, memo callback, effect, and event. Analyze module top-level expressions for each runtime use; analyze function bodies only through entry exports, JSX component invocation, recognized callbacks, or direct resolved calls. Merely importing a function does not execute its body. Treat calls to referenced Server Functions as server-function execution, including references delivered as props. The entry function starts at call depth 0; each resolved direct local call increments depth by 1. Execute bodies through depth 2. Recursion or depth 3 produces `unknown-phase` at the call. Import and reexport edges do not consume the call budget. Respect local symbols that shadow globals. Supported guards compare `typeof window` with the string `undefined` using ===/!==/==/!=, in either operand order. The browser branch of if/else/ternary, &&/|| short-circuiting, and a dominating early return is protected; `typeof window` itself is safe. A recognized browser guard must refer to the unshadowed global window. A check against a local variable named window cannot protect reads of global document or localStorage. Protect only reads of window/document/localStorage in the dominated branch. Unrecognized guards do not prove safety; emit `unknown-phase` when their result is required. An environment check does not protect code executed before the check. Helpers used from multiple phases retain each use.

Callbacks registered in `useEffect`/`useLayoutEffect` and function values assigned to client-owned intrinsic JSX event attributes (`on` followed by an uppercase letter) use the browser phase; custom component callback props require analysis of the resolved consumer and otherwise produce `unknown-phase`. Their arguments are evaluated in the caller's phase. `useMemo` and both kinds of `useState` initializer run during render. Do not invent a phase for an unknown library callback. `next/dynamic` with a literal `ssr: false` object within the client avoids the dynamic component's SSR phase; unresolvable references or values produce a limitation. NSG003 does not check general hydration differences.

Value model: serialization supported/rejected/unknown, plus independent sensitivity origins. Traverse assignments, aliases, destructuring, object/array literals, and known spreads, tracking sensitivity by field. Analyze JSX props only when sender and destination are resolved; do not treat a prop named Action as a remote reference. Accept Date, Map, Set, ArrayBuffer/TypedArray, primitives, Symbol.for, elements, Promise, and recognized references according to React; check known contents. An exported function imported from a `use client` module crosses as a client reference, not an ordinary server-created function. JSX children are prop values: a server-owned element sends rendered output and does not pull its component implementation into the client graph. Unknown Promise results require `unknown-value`; accept an otherwise unresolved client reference without inspecting its implementation for serialization. Server-created functions, custom classes, null prototypes, and local Symbol values are NSG004 rejections. Constructors and Symbol/Promise/Object.create summaries require unshadowed built-in identity; unmodeled constructors produce unknown. [S2](RESEARCH.md#s2)

NSG005 uses only key or export declarations, without name heuristics or regex secret detection. Exported origins are identified by file, export, and field array. Value evaluation follows at most two nested local function calls from the sink expression, including parameters and returns. A third call, recursion, computed operations, mutations, or unknown transformations yields `unknown-value` at a supported transfer sink. Explicitly selecting a DTO without a confidential field removes that field from the destination, not its origin. Do not treat hashing or encryption as automatic sanitization.

Confidential-data sinks: client props, the return value of a client-referenced Server Function, a value exported toward the client, and static `next.config.env`. Distinguish a private value evaluated on the server and transmitted from a `process.env` read that Next substitutes on the client: the latter is NSG006, not an NSG005 leak. Without sensitivity configuration, NSG005 reports `sensitivityConfigured: false` and does not infer categories. Unknown Next configuration downgrades NSG006 to medium confidence and adds a limitation.

### Transfer and diagnostic rules

Track serialization as supported/rejected/unknown and sensitivity as a set of declared origins per value path. Object properties use exact static keys; arrays use known indices; Map checks keys and values; Set checks elements. Later known spreads override earlier fields using JavaScript object order. Conditional branches union possible origins: a violation is high confidence only on a statically known path or when every possible alternative violates the same condition; otherwise emit `unknown-value`. Unknown mutation invalidates the affected value from that point. Constant primitive expressions and `await` of a known Promise preserve facts; assertions and types cannot prove runtime safety. Cycles or unsupported operations yield unknown with a limitation at the sink. A known rejected or sensitive field can still be reported when another field is unknown; retain the limitation for the unknown field.

Recognize unshadowed `process.env.KEY` and `process.env['KEY']` with a literal key. Public keys use the NEXT_PUBLIC_ prefix or a statically resolved config env key. Exclude Node's built-in `NODE_ENV` from NSG006. Computed keys, aliases of process/env, and destructuring produce `unknown-value` for NSG005/006 when client-reachable; constant propagation must not treat these as framework-inlined reads. A declared public key is an NSG005 source when its value reaches a client use. An env config key declared secret/private is itself a publication-policy sink, even when its value expression is unresolved. The diagnostic states that the key is configured for public substitution; it does not assert that an unused key has appeared in a served bundle. No secret value needs to be read. [S28](RESEARCH.md#s28)

Valid Server Function references do not expose their bodies or encrypted captures. Analyze explicit returns, but do not claim that an inline function's encrypted closure is a plaintext leak. `bind`, higher-order wrappers, and computed function exports whose reference identity cannot be resolved produce `unknown-value`; do not classify them as ordinary functions solely from their type. [S3](RESEARCH.md#s3), [S4](RESEARCH.md#s4)

NSG001's file-system summary covers fs, node:fs, fs/promises, and node:fs/promises. A retained runtime import or reexport establishes module reachability; the import-retention table determines whether an ordinary TypeScript import survives. Symbol resolution identifies actual API uses and selects value exports. Other Node built-ins are unmodeled external dependencies. NSG002's hook table contains only useState/useEffect/useReducer from react and useRouter from next/navigation; use/useId are allowed. The named hook imports and resolved calls are restricted only in rsc uses; general hook validity in server-handler/server-function bodies is outside NSG002. [S9](RESEARCH.md#s9), [S29](RESEARCH.md#s29)

Emit one finding per rule, primary site, origin, and destination; aggregate contexts and retain the shortest evidence path, breaking ties by POSIX path and offset. NSG001/002 API diagnostics point at the incompatible use when resolved. A retained restricted import without a resolved use points at its import declaration. Do not duplicate that import finding when its resolved use already identifies the same originating binding. Marker diagnostics point at the first client/server boundary import. NSG003 points at the global read, NSG004 at the offending prop value, NSG005 at the sink, and NSG006 at the env read. A site may legitimately have both NSG001 and NSG005. `off` prevents that rule's findings; coverage limitations remain. `high` confidence requires all evidence required by the rule; only NSG006 with dynamic config emits a medium-confidence finding. During detection, limitations affect their dependency path and relevant rules, not unrelated resolved paths. PR novelty/resolution uses the conservative comparison policy specified below.

## CLI contract

Parse arguments in strict mode. One positional root and one value per flag; reject every repeated flag, unknown options, extra positional values, and invalid formats with 2. Without a subcommand, show help and return 0. Accept only `scan`; help/version must be used alone or with scan, without analysis options. Paths supplied as CLI arguments are relative to cwd; config projectRoots/exclude/export paths are relative to the scan root. [S21](RESEARCH.md#s21)

| Interface | Semantics |
| --- | --- |
| `scan [root]` | Root defaults to cwd; analyze current state, including uncommitted files. Return 2 if no apps are detected. |
| `--config <path>` | UTF-8 JSON; default to next-static-guard.json in the root, or internal policy if absent. |
| `--format terminal\|json\|markdown` | Terminal by default; one format per execution. |
| `--output <path>` | Without this option, stdout; with it, write the report atomically. Reject symlink targets and paths colliding with source, metadata, configuration, or baseline inputs. Replace only an existing valid Guard report of the requested format. Do not create missing parent directories. |
| `--base <git-ref>` | Compare current state against the merge-base of HEAD and ref. Requires installed Git >=2.47.0, supporting `--no-lazy-fetch`. |
| `--baseline <path>` | Read a previously saved, compatible JSON v1 report; mutually exclusive with --base. |
| `--strict-coverage` | Return 2 if coverage is partial within scope, including comparison uncertainty. Defaults to false. |
| `--help`, `--version` | Do not analyze or write; exit 0. |

Logs go to stderr. Exit 0 without blocking findings, 1 with blocking findings, and 2 for operational/config/base failure or strict partial coverage; precedence 2 > 1 > 0. A timeout is 2; SIGINT/SIGTERM exit 130/143 after temporary cleanup. Reports always state coverage: 0 does not imply complete coverage. [S15](RESEARCH.md#s15)

After successful analysis, write the report even for exit 1 or strict-coverage exit 2. Invalid inputs, Git failure, timeout, and output IO failure emit a sanitized stderr error and leave the previous report intact. Atomic output uses an exclusively created temporary sibling file followed by rename; clean up on failure. Terminal/Markdown reports carry a `Next Static Guard report v1` heading so replacements can be identified. No flags create suppressions or modify analyzed files.

## Configuration and reports

Closed internal schemas, Ajv2020 with strict and allErrors, without coercion or implicit defaults. Set `additionalProperties: false` on every object; apply defaults during subsequent normalization. Store schemas in `schemas/config.v1.json`, `schemas/report.v1.json`, and `schemas/case.v1.json`. Do not accept comments in config JSON. [S21](RESEARCH.md#s21)

| Config field | Type and default |
| --- | --- |
| schemaVersion | Required integer, only 1. |
| projectRoots | Nonempty array of unique relative strings; default `["."]`. Identifies apps; shared sources may be under the scan root. |
| exclude | Array of relative globs; empty by default in addition to fixed internal exclusions. No negation, absolute paths, or `..`; picomatch dot true, nocase false. |
| rules | Object mapping NSG001..NSG006 IDs to off/warn/error; omitted entries use the shipped ruleset defaults (warn in ruleset 1.1.0). |
| sensitive.env | Array of `{name, category}` objects; name is an exact identifier, category secret/private; empty by default. |
| sensitive.exports | Array of `{file, export, field, category}`; file is an exact relative path, field is a string array defaulting to empty; other fields required. Empty by default. |
| exceptions | Array of `{fingerprint, ruleId, status, reason}`; status false-positive/accepted-risk, reason 1..500 characters; empty by default. |

Only schemaVersion is required in config; all other fields are optional. Omitting sensitive is equivalent to `{env: [], exports: []}`; a supplied declaration requires the fields in its row. Normalize paths to POSIX for identity; resolve realpath before reading. Reject conflicting repeated categories, duplicate exceptions, and roots outside the scan. Do not accept severity or confidence overrides. `error` enables blocking only if the rule is certified, severity is high/critical, and confidence is high; requesting it for an uncertified rule retains warn and emits a warning. When enabled, NSG006 is `warn` even if `error` is requested; `off` disables its findings. Do not show exception reasons in public reports: only status and fingerprint, to avoid repeating sensitive user-supplied text.

All supplied config strings are nonempty; environment names match `[A-Za-z_][A-Za-z0-9_]*`; fingerprints are 64 lowercase hexadecimal characters. Each export declaration requires file/export/category; field alone defaults to an empty array. A supplied sensitive object may omit either array. Deduplicate identical sensitivity declarations and reject differing categories for the same origin. Exception identity is `(ruleId, fingerprint)`; it suppresses matching findings while preserving their comparison status and evidence. Unmatched exceptions are stale only under complete relevant coverage; otherwise keep them unresolved. Reject duplicate exception identities. Config paths accept `/` separators, with `.` permitted only as a project root; no absolute paths, empty segments, or parent traversal. Control characters are invalid in config identifiers and paths.

Minimal configuration:

```json
{
  "schemaVersion": 1,
  "sensitive": {
    "env": [{ "name": "PAYMENT_TOKEN", "category": "secret" }],
    "exports": [
      { "file": "lib/server/profile.ts", "export": "profile", "field": ["email"], "category": "private" }
    ]
  }
}
```

JSON report v1 requires `schemaVersion: 1`, `toolVersion`, `rulesetVersion`, `fingerprintVersion: 1`, `policyHash`, `policy`, `projects`, `scope`, boolean `sensitivityConfigured`, `coverage`, `comparison`, `findings`, `summary`, and `metrics`. Ruleset `1.1.0` is the MVP ruleset. projects is an array of `{root, nextVersion, reactVersion, reactDomVersion, typescriptVersion}` with string or null versions. scope is `{roots, exclusions, unsupported}`: arrays of relative paths, globs, and `{file, feature}` records; feature is pages-router/metadata/proxy/instrumentation/edge/mdx/commonjs. coverage is `{status, limits}` with status complete/partial; comparison is `{mode, baseCommit, status}` with mode none/git/baseline, string or null baseCommit, and status complete/partial/not-applicable. metrics contains durationMs, sourceCount, edgeCount, and sourceBytes, all nonnegative numbers, integers except durationMs. In Git mode, counts sum the two snapshots and duration includes their analysis and Git IO. No timestamps or invented empty versions.

policy is `{source, currentPolicyHash, changedFields, ignoredCurrentConfig, effectiveRules}`. source is default/current/base/explicit; currentPolicyHash is a SHA-256 string or null when the current config is invalid; changedFields contains only sorted top-level config field names; ignoredCurrentConfig is boolean. effectiveRules maps each rule ID to `{requested, effective, certified}`, where requested/effective are off/warn/error and certified is boolean. In Git mode, changedFields compares normalized current/base policy without exception reasons; an invalid ignored current config adds `config-invalid` to changedFields and a stderr warning, without invalidating a valid base policy. It never echoes input values. In other modes changedFields is empty and ignoredCurrentConfig false. policyHash always identifies the policy actually used.

A finding requires ruleId, message, severity critical/high/medium/info, confidence high/medium, location `{file, start:{line,column,offset}, end:{line,column,offset}}`, contexts, evidence, string recommendation, fingerprint, status new/existing/aggravated/unverified, boolean suppressed, and boolean blocking. Locations use 1-based lines/columns and 0-based UTF-16 offsets, with an exclusive end. evidence is an ordered array of `{kind, location, symbol}`, without literals or source snippets; kind is import/reference/api/phase/value/source/sink, and symbol is string or null. Limitations require code, nullable location, and affectedRules; codes: unsupported-version, unresolved-import, conditional-resolution, dynamic-config, unsupported-syntax, unknown-value, unknown-phase, source-excluded, source-budget, uncertain-runtime, comparison-incomplete, fingerprint-collision. summary requires nonnegative integer counts total, new, existing, aggravated, unverified, suppressed, and blocking, plus resolved, a list of resolved fingerprints, never active findings. Total includes suppressed findings; the four status counts sum to total, and blocking excludes suppressed. All described fields are required; explicit absent values are null or empty arrays.

contexts is a sorted unique array of the context enum; affectedRules is a sorted unique array of rule IDs. Suppressed findings also require `suppressionStatus` false-positive/accepted-risk; otherwise suppressionStatus is null. Coverage records require `snapshot` current/base and `projectRoot` (relative path or null). Deduplicate by snapshot/projectRoot/code/location/affectedRules. Complete coverage means no in-scope limits; listed out-of-scope features alone do not make it partial. comparison mode none uses baseCommit null and status not-applicable; baseline uses baseCommit null; git uses the resolved merge-base hash. comparison is partial when any relevant base/current limitation prevents establishing novelty or resolution. summary.resolved includes a base fingerprint only when its absence is established under complete relevant current coverage; sort and deduplicate it. Schemas enforce nonnegative integer offsets, positive line/column values, SHA-256 formats, enums, and all required fields; cross-field invariants are checked after schema validation.

Sort findings and limitations by path, offset, and rule/code; null locations sort first, with snapshot/projectRoot as tie breakers. Sort all set-like arrays; preserve evidence path order. Pretty-print JSON with two spaces and a final newline. Terminal/Markdown include tool/ruleset, apps and versions, coverage/limits, policy changes, each finding's rule/severity/confidence/status/location, trace, recommendation, suppression, and counts. Show every finding and limitation without silent truncation. Escape Markdown metacharacters, HTML delimiters, and controls in user-derived names; terminal output has no colors. Messages use internal templates. Only metrics change between identical runs. Parsing logs state the file and code, never a raw diagnostic containing source.

Fingerprint v1 = SHA-256 of canonical JSON for the array `[1, ruleId, path, qualifiedSymbol, siteShape, ordinal, origin, destination]`. siteShape normalizes the AST by replacing all literal values with their type and omitting trivia/positions; ordinal distinguishes sites with the same shape within the symbol. origin/destination are symbolic IDs, not the complete import chain. QualifiedSymbol uses exports and lexical names; anonymous symbols use a lexical index. Do not match file renames in v0.1: they count as a resolution plus a new finding. A detected collision produces a limitation and unverified status. PolicyHash is SHA-256 of canonical JSON with sorted keys for the normalized policy, excluding exception reasons.

Canonical JSON uses recursive lexicographic object-key order, preserved array order, UTF-8 encoding, and JSON.stringify number/string encoding without spaces. Normalize each AST site into `[SyntaxKind, children...]` in source order: identifiers keep their names, literals become string/number/bigint/boolean/null tokens, and type-only nodes/trivia/positions are omitted. The site is the primary diagnostic expression or import declaration. qualifiedSymbol joins enclosing named declarations with `/`, using `<module>` outside functions and `<anonymous:n>` for zero-based anonymous sibling order. ordinal is zero-based source order among equal site shapes in that symbol. A symbol ID is `relativeFile#qualifiedSymbol`; API IDs use `package#export`, globals `global#name`, and env origins `env#KEY`. Configured export origins append a JSON field-path array. Destination IDs use `client`, `rsc`, `server-execution`, or the resolved client symbol plus prop name; NSG005 uses that sink ID or `config#env.KEY`. NSG001/002 use the restricted module/API origin and incompatible context destination; NSG003 uses the global origin and server-execution; NSG004 uses the value origin and client prop; NSG006 uses env origin and client. Never include confidential literal values in identity. Compare normalized tuples before hashing to distinguish accidental identity collisions from intentional grouping.

PolicyHash includes all normalized config fields, including requested rule levels and exception status/fingerprint/ruleId, excluding only reasons. Sort roots/exclusions, env origins, export origins, and exception identities before hashing; object keys are canonical. Effective certification belongs to rulesetVersion, not policyHash. Ship certification metadata with the engine: per rule, evaluated profile, eligibility, default level, and results reference. Ruleset `1.1.0` sets eligibility to false, default level to warn, and results to null for all rules. A certified ruleset provides a public results URL; repository validation output is recorded in docs/RESULTS.md. A rule cannot block outside its certified profile.

## Comparison and policy protection

Git uses execFile with separate arguments and shell false, without hooks, checkout, or fetch. Every invocation starts with `git --no-lazy-fetch --no-replace-objects` and uses `GIT_TERMINAL_PROMPT=0`; a missing object in a partial clone returns 2 instead of downloading it. Validate the ref with `rev-parse --verify --end-of-options <ref>^{commit}`; compute all merge-bases with HEAD: none or multiple bases is error 2. Read names with ls-tree -rz and contents with cat-file --batch, using a byte protocol without filters/smudge. Read only Git objects. The virtual host preserves manifests and symlinks from the base tree; a symlink outside the snapshot produces a limitation. Current HEAD analysis includes filesystem changes; do not write objects or alter the index. [S24](RESEARCH.md#s24)

Run Git from the repository containing the scan root and map its tree paths back to that root. Require HEAD to resolve to a commit. Base policy is root-relative next-static-guard.json from the merge-base tree, or default policy if absent; an invalid base policy returns 2. `--config` in Git mode must point outside the current worktree: it is the caller-supplied CI policy used for both snapshots. Use `--no-optional-locks`, `-c core.fsmonitor=false`, GIT_CONFIG_NOSYSTEM=1, and GIT_CONFIG_GLOBAL pointing to the platform null device. Inherit only PATH, temporary-directory variables, and Windows SystemRoot/ComSpec/PATHEXT needed to start Git; add fixed locale and prompt/config controls. Do not inherit GIT_DIR, GIT_WORK_TREE, GIT_CONFIG_COUNT, trace, SSH, or credential variables. No Git subcommand requiring transport is allowed. [S24](RESEARCH.md#s24)

Evaluate both snapshots with the same engine version and **the base policy** in Git mode, unless an explicit --config outside the worktree overrides both. Report the current config's hash and differences without applying them to PR blocking. Exceptions added in the PR do not automatically suppress new findings. Local/baseline modes use the current policy. A baseline requires matching schemaVersion/rulesetVersion/fingerprintVersion/policyHash, the same normalized scope roots/exclusions, and complete analysis/comparison coverage; otherwise return 2. A noncomparison baseline with comparison.status not-applicable is valid. Differences in toolVersion alone are allowed only with the same ruleset and fingerprint semantics. Every released semantic rule/analysis change increments rulesetVersion. Suppressions in a saved report cannot replace current exceptions. Do not create or prune a baseline automatically: save it with scan --format json --output and update it through an explicit local action.

Without comparison, all findings are new. With comparison, the same identity means existing; it becomes aggravated when the current finding is high/critical with high confidence and its severity or confidence increases relative to the base. Severity order: info < medium < high < critical; confidence medium < high. Compare those values rather than the blocking boolean, to avoid aggravating identical debt. Absence from a complete base means new. If base limitations prevent establishing novelty, use unverified status without automatic blocking; comparison is partial and strict returns 2. A finding in a source absent from the complete base path inventory is `new`, provided base discovery and the relevant app mapping succeeded; an unrelated base limitation does not change that status. For unmatched findings in preexisting sources, any base limitation affecting the same rule prevents proving novelty and yields `unverified`. A base finding is resolved only when the current scan has no matching finding and no limitation affecting that rule. This conservative rule-wide fallback is the v0.1 comparison policy. Existing debt does not block. Reappearance after resolution is new. Warn about stale exceptions on stderr and retain them until explicit editing.

## Operational limits

Fixed v0.1 budgets: 2 MiB per source, 10 MiB per project metadata or tool config/baseline JSON, 50,000 reached sources, 512 MiB total source text per snapshot, 120 s per complete execution, two call hops, and 64 recursive value-evaluation steps from a sink expression. Timeout or oversized required tool config/baseline is error 2. Project-source/metadata caps produce partial coverage; unreadable reached sources use `source-excluded`, size/count/depth budgets use `source-budget`, and call-depth/recursion uses `unknown-value` or `unknown-phase`. Do not treat recursive data as serializable. Single-threaded processing, reads with maximum concurrency 8; no workers or persistent cache. Retain reached ASTs for one snapshot at a time, then release them; comparison retains base findings and summaries, not both Programs. Value depth starts at 0 and increments for every recursive evaluation, including wrappers and field values; depth 65 emits `source-budget`. Call depth is counted separately.

Internal exclusions: .git, .next, node_modules, dist, build, coverage, and known report outputs; do not honor .gitignore as an implicit exclusion of reached code. Imports into excluded sources produce a limitation. External resources, `.env*`, credentials, and process environment values are not read. Operational PATH/TMPDIR variables used to locate Git/temporaries are not analysis data; Git runs with a minimal environment and no network. Deduplicate symlinks by realpath without following directories outside the root. Exclude generated files only through fixed directories/globs; do not guess from comments.

Measure performance and compatibility with the protocol in [Validation](VALIDATION.md). A failed acceptance check prevents release until corrected.
