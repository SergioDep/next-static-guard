# NSG001: Server dependency in client code

Profile: Next 16.3.8, React/React DOM 19.3.0, App Router, standard Turbopack. Ruleset 1.1.0 level: `warn`, uncertified. Severity: high. Confidence: high.

## Detection

A runtime dependency from a client use reaches a server-only marker or retains a restricted import or use from the architecture API table. Unconsumed runtime reexports retain module restrictions. TypeScript binding elision follows the consuming app's `verbatimModuleSyntax`; JavaScript retains ordinary import dependencies. A module-level Server Function import is a reference and keeps its implementation on the server.

## Example and correction

A Client Component imports a helper that imports `server-only`.

Keep the helper on the server. Call it from a Server Component and pass a small DTO, or expose an async Server Function and pass its reference.

## Valid controls

Explicit type-only imports, pure shared utilities, and valid Server Function references do not violate this rule.

## Evidence and limitations

The marker finding points to the incompatible boundary import. An API finding points to its resolved use or, when no use is resolved, the retained restricted import. Evidence records the resolved dependency chain.

Unknown exports, external packages, conditional resolution, and uncertain runtime retention produce limitations. Importing an unrelated Next export does not establish a server API use.
