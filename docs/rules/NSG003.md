# NSG003: Browser global during server execution

Profile: Next 16.3.8, React/React DOM 19.3.0, App Router, standard Turbopack. Ruleset 1.1.0 level: `warn`, uncertified. Severity: high. Confidence: high.

## Detection

A direct read of the unshadowed identifier `window`, `document`, or `localStorage` occurs during confirmed module evaluation or rendering on the server without a recognized dominating browser guard.

## Example and correction

A module marked `use client` initializes a constant from `window.location`.

Move the read into an effect or client event handler, or protect it with a dominating check against the unshadowed global `typeof window`. Preserve render behavior without relying on a browser value during SSR.

## Valid controls

Client effect/event callback bodies and recognized browser branches are valid. Callback registration arguments are still evaluated in the caller's phase.

## Evidence and limitations

Evidence identifies the global read, its execution phase, and the local call path. `use client` alone does not disable SSR.

The local call budget is two hops. Unmodeled callbacks, mutations, guards, or class component execution produce `unknown-phase`. General hydration differences and browser-global access through `globalThis` properties are outside this rule's v0.1 pattern set.
