# NSG006: Private environment read in client code

Profile: Next 16.3.8, React/React DOM 19.3.0, App Router, standard Turbopack. Ruleset 1.0.0 level: `warn`, uncertified. Severity: medium. Confidence: high unless explicitly stated below.

## Detection

Client-reachable code directly reads a static environment key without `NEXT_PUBLIC_`, without a recognized config publication entry, and other than `NODE_ENV`.

## Example and correction

A client-imported helper reads `process.env.PAYMENT_TOKEN`.

Evaluate the private variable on the server and transmit only appropriate public data. A secret must not be made public merely to fix client substitution.

## Valid controls

Server-only reads, nonconfidential `NEXT_PUBLIC_` values, recognized public config entries, and ordinary shared constants are valid.

## Evidence and limitations

The primary location is the static environment read. Evidence identifies the key and client use. High confidence requires resolved publication policy; dynamic config produces medium confidence plus a limitation.

This is a functional warning, not proof that a private value leaked. Computed keys, environment aliases, and destructuring are limitations because they do not establish framework substitution. The rule cannot block, even after an error request.
